# 内容规范

## 一、目标读者与写法

上班白领，尤其是日常使用 AI 的办公室职业人群。通勤 / 午休碎片时间在手机上扫读，时间少、耐心低，要「短、快、准」拿到想看的信息点。

- **结论先行**：头部固定「本期速览」，七部分各一句信息点（给判断，不给导航、不给统计口径）；每个板块先给一句判断，再给必要证据。**速览七条的行首标签固定为：`一 要闻` / `二 报告` / `三 工具` / `四 版本` / `五 插件` / `六 MATLAB` / `七 AutoResearch 追踪`**——第七条要直接点出这是 AutoResearch 方向的持续追踪，不许写成「论文与开源」「论文与工具」这类泛称，读者凭标签就要知道这是固定栏目而不是零散推荐。
- **信息密度 = 有效信息点 ÷ 阅读成本**，不是字数。开头三句定生死，每 300 字左右拆段。
- **不写实施方法**：安装命令、分步操作、最短上手路径、配置参数一律不列。需要时统一一句「把项目名或链接交给 AI Agent 即可完成」。
- **保留人需要判断的内容**：发生了什么、关键数据、看点、适用场景、局限、一手链接。厂商自测口径、版本依赖门槛仍要标。
- **不堆技术标识符**：避免成串配置名与函数名，一律改成功能结论。
- 句子长短参差，不要为了整齐把每段写成一个长度；结尾不升华，平平实实收住。

## 二、固定七部分（顺序不变，每期必含）

### 一、过去 24 小时 AI 核心要闻
3–5 条，覆盖行业重大动态、产品发布、政策监管。每条：标题 + 一句要点 + 来源链接（纯文本，放在内容之后）。

### 二、官方新报告
大标题固定「**二、官方新报告**」，不带来源数量、不带「19 个来源」。

- 19 个监控源过去 24h 新发布的技术报告 / 论文，**必须核对一手官方链接**，统一「先各自官网、后 arXiv 补漏」，详见 [monitor-sources.md](monitor-sources.md)。
- 挑最主要 **3 份深讲**，每份四要素：**出发点 / 做法 / 局限 / 看点**。
- 末尾附其余新报告简要清单，**只列窗口内**；无则一句结论带过，不列窗口外索引。
- 当日不足 3 份 → 按实际数量输出，在底稿里说明缺口，不用旧报告凑数。
- **回看规则（2026-11-13 用户定）**：窗口内 0 份 / 不足时，按日期倒序回看近日（前一天优先）官方新报告，**此前日报从未发过的够格内容可以收录深讲**；收录时把发布日期作为事实自然写出，正文不写「回看」「补发」「窗口外」「凑数」等编辑部说明。已在前几期发过的成果不得重复。
- **「已发出」核对方式（2026-11-13 用户定）**：判断某成果此前是否已发过，以**公众号「算法牛马」实际发出的文章为准**——搜索该公众号已发布文章（如 WebSearch `算法牛马 牛马AI日报` 或 site 限定 `mp.weixin.qq.com`）确认；本地工作区的 md / HTML 底稿不代表已发出（2026-11-12 期即试跑未发出，视作未发布）。草稿箱里有草稿但未群发，同样不算已发出。
- 「局限」是四要素之一，每日内容不同，保留；常见口径：发布方自测、自建基准既出题又参赛、无独立复现、未开源、仅供研究、版本依赖门槛。
- 模型 / 产品发布公告、方案介绍博客不算技术报告。

### 三、今日最值得推荐的 AI 工具用法
检索科技博客、公众号、小红书、GitHub、B 站等，精选 **1 个**最有价值的工具技巧。给：名称 / 平台作者 / 链接 / 思路 / 适用场景 / 看点。无高价值分享则如实说明并给次优推荐；实施步骤按写法规范一句带过。具体工具局限（未开源、仅供研究、CLI 遥测）要写。

### 四、DeepSeek-Harness 最新版本
检索最新版本号与更新说明：版本号 / 日期 / 主要更新 / 变更点。检索不到更新 → 如实写「今日无新增」。

### 五、Awesome DSH Plugin 清单更新
检查 `github.com/awesome-dsh-plugin/awesome-dsh-plugin`，按「新增/更新条目 → 实用插件重点推荐（标注推荐标签及理由）→ 榜单头部排名变化」组织。

- 每条给名称、分类、**GitHub 星标数**（格式 `GitHub ★ 4`，有仓库必标）、一句话功能、适用场景、来源链接。
- 「新增/更新条目」**一句人话概括**即可（今日新增约 N 条、约 N 条更新安装信息、N 条下架），明细不逐条列；重心放在有功能解读与适用场景的「实用插件重点推荐」。
- **排名无变化时只给一句「今日无」，不解释理由**，不写 README 声明、索引顺序、字段说明等补充说明。
- 禁止成串罗列插件名 + PR/Issue 编号、逐条 PR 链接、提交次数细分、机器人提交说明、精确到分钟的 UTC 时间窗、同一段内重复的统计数字。

### 六、MATLAB / Simulink × Agent 编程动态
**单一板块**，只写过去 24 小时内的**官方动态 + 工具动态**，不拆 ①②③④ 等小节堆叠、不单列「近期官方消息」「官方工具全量表」「上手路径」。

- 核对 MathWorks 官方新闻稿 / 博客 / GitHub 仓库一手链接。官方总入口 `https://www.mathworks.com/products/agentic-ai.html`；版本以 GitHub Releases 为准（官网 Hub 的 What's New 常滞后）。
- 工具给名称、版本 / **GitHub 星标数**（有仓库必标，格式 `GitHub ★ 6,915`）、一句话功能与适用场景。
- 保留工程师最终验证责任、版本依赖门槛、厂商自测口径这些**具体事实**，但不写通用边界 / 免责套话，不写最短上手路径。
- 时间统一北京时间。

### 七、AutoResearch 论文与开源动态
大标题固定「**七、AutoResearch 论文与开源动态**」（2026-11-15 用户定稿）。过去 24 小时 AutoResearch 方向的论文、科技报告与重点开源项目动态。

**方向优先级（2026-11-15 用户定，取稿第一位）**：**深度学习 AI 模型的自我迭代（self-iteration / self-evolution）**是首选方向——模型或训练流程在无人工介入下自行改进自己。其余 AutoResearch 内容（自动化科研流程、AI scientist、文献与实验编排 agent）属次级，够格才收，但不得挤掉自我迭代方向的条目：窗口内有自我迭代成果时，深讲名额优先给它。

**重点应用场景（同等优先级）**：**给定一套已有数据集，让模型不受限地自学习与迭代**——任务类型不限、迭代次数与手段不限，模型自主跑到更好的结果。落在这条场景里的研究 / 项目优先收录，重点看三件事：
- **架构优化设计**：自主搜索 / 改写网络结构、算子、层数与连接方式；
- **超参数迭代**：自动搜索学习率、批大小、优化器、正则、训练配比等；
- **自我训练与自我评估**：自造训练信号、自评分、多轮自我改进循环、自选数据与课程。

**降级判定**：只有"agent 帮人跑实验 / 写代码 / 读论文"、模型本身没有自我改进环节的，不算自我迭代方向，按次级处理或收（与其硬凑，不如写「今日无」）。

- **论文**：知名 SCI 期刊论文、知名会议论文与 arXiv 预印本都查，**高影响因子 SCI 论文与顶会论文优先**。期刊 / 会议论文标注期刊或会议名与收录日期，arXiv 标注「预印本」。窗口内挑最重要 1–3 条，每条给：标题 / 团队与机构 / 一句话方法或发现 / 看点 / 链接（DOI 或 arXiv）。
- **科技报告**：与第二部分同口径——模型 / 产品发布公告、方案介绍博客不算。
- **开源项目**：重点看 GitHub 上 AutoResearch 方向的项目动态（新项目、重大版本 release、重大功能更新），也包括以自有网站为主页的开源项目；给名称、**GitHub 星标数**、一句话功能与适用场景、链接。只有零散代码提交、无 release 或官方公告的不收。
- **星标数写法（2026-11-15 用户定，开源项目必标）**：每条开源项目在信息行标注 GitHub 星标，格式统一 `GitHub ★ 6,915（11-15 抓取）`——数字用千分位，括号内给抓取日期，明确是抓取时点口径而不是「当前永久值」。星标数必须来自 `api.github.com/repos/{owner}/{repo}` 实查，**查不到（私有、未开源、无仓库）就不标，宁可缺也不编**；星标极低（个位数）也照实写，不因不好看而省略。仓库地址同样必须实查存在（返回 200），不能凭项目名拼 URL。
- **开源项目与论文并列呈现**：接着论文的 ①② 往下排序号，用与论文相同的标题行 + 信息行 + 三段正文（做法 / 局限 / 看点，与论文条目同序：事实 → 边界 → 判断），不另起灰底卡片或蓝条块。
- **检索式与关键词**（照此组合，实际用到的写进核查底稿便于复现）：
  - 自我迭代主体：`self-evolving` / `self-evolution` / `self-improving` / `recursive self-improvement` / `self-iterative training` / `self-rewarding` / `self-training` / `self-evaluation`
  - 架构与超参：`neural architecture search` / `NAS` / `automated architecture design` / `hyperparameter optimization` / `AutoML` / `agentic AutoML`
  - 组合限定：上述 + `dataset` / `given dataset` / `no human intervention` / `autonomous` 提高命中精度；arXiv 无机构字段、别名与通用词（`AutoML`、`agent`）误命中高，须读摘要确认「模型自己改自己」，不核对不收。关键词检索有漏检，不宣称「已完整覆盖」。
- 检索不到够格内容 → 如实写「今日无」，不给理由；不用窗口外内容凑数，回看规则与第二部分相同（近日未发过的够格内容可收录，正文不出现「回看」「补发」等措辞）。**回看也只在自我迭代方向内回看**，不因为是次级方向就放宽凑数。

## 三、收录与判定口径

| 情形 | 处理 |
|---|---|
| 同一成果官网与 arXiv 都出现 | 只计一次，以官网为主 |
| arXiv 预印本 | 标注「预印本」，不等同官方技术报告 |
| 期刊 / 会议论文 | 标注期刊或会议名；arXiv 同文重复只计一次、以正式发表为准 |
| 模型 / 产品发布公告 | 不计入技术报告（可进第一部分要闻） |
| 方案介绍 / 产品博客 | 不计入技术报告 |
| 官网条目无发布日期 | 无法确认落在窗口内，不收 |
| 只有 GitHub 代码提交 | 属提交不是报告发布，不收 |
| 厂商自测数据 | 标「发布方自测」，不写成独立结论 |
| 窗口外成果 | 不写、不索引、不解释「为什么没收」；**唯一例外**：第二部分窗口内 0 份时按回看规则收录（见上），且此前日报未发过 |

## 四、公众号正文禁止清单

**编辑部说明**：检索窗口、「为保证当日动态完整」、逐家核查口径、Star / 版本核对口径、读表说明、13 家 / 19 家核查看板、「本文不展开 / 不计入 / 不凑数 / 按日期计入 / 最近两条列在下方」、文末「本日报以事实为准」「公众号不支持外链」声明。

**编辑部盘点 / 解释文章怎么组织**：来源计数与核查范围（「19 个来源」「13 家」）、凑数与缺口交代（「补上第 3 份」「其余 16 个没有」「不足 3 份」）、板块盘点框（「今天有 2 条官方动态」「今天是一次集中批量更新」「没有新新闻稿」「24 小时内有一次…」）、眉标自报条数（「本期速览 · 6 个信息点」→ 只写「本期速览」）、「（节选）」「在列」「按官网为主只计一次」、窗口外日期的核查解释。删掉盘点框后不补替代句，直接进内容。

**窗口外内容**：禁止「其他值得留意（窗口外）」「窗口外索引 / 不计入 / 不凑数」「近期但窗口外官方消息」「按日期计入」等板块与措辞；不单列窗口外版本历史。第二部分按回看规则收录的报告属正常内容，发布日期作为事实写出即可，但不得出现上述任何「窗口外」措辞。

**通用套话**：「大家都知道」的边界与免责声明、每日重复出现且无信息增量的板块、给「无变动」找理由。

**机器清单**：见第五部分「新增/更新条目」规则。

## 七、贴图摘要

用途：公众号「图片消息 / 贴图帖子」的正文。读者在发现页划过时不点开长文也要能一眼看清今天有哪几件事。

**做法：直接搬日报头部的「本期速览」，一字不改。**（2026-11-18 用户定稿）摘要是速览的纯文本副本，不另写、不提炼、不重排、不再做二次编号——日报写好速览，摘要就等于做完了。写摘要的时间应该花在核对速览原句上，不是重新组织语言。

**格式**：UTF-8 纯文本，落盘为 `每日AI晨报_{date}_摘要.txt`。

- 第 1 行：`牛马AI日报 · YYYY 年 M 月 D 日`
- 空行
- 之后**逐行照抄速览七条**，一条一行，行首保留原标签 `一 要闻` / `二 报告` / `三 工具` / `四 版本` / `五 插件` / `六 MATLAB` / `七 AutoResearch 追踪`，标签后接 `｜` 再接原句。
- 唯一允许的改写：把 HTML 里的 `<strong>` 强调剥掉，只留纯文本。

**规则**：

- 不改写、不压缩、不合并、不拆句、不调顺序、不换词；速览写了什么就是什么。
- 不自行加 `1.` `2.` `3.` 编号，也不用圈号 ①②③ —— 速览的编号就是七个板块标签本身。
- 「今日无」的板块**照抄保留**（如「六 MATLAB｜今日无。」），不删行、不补位。
- 不新增数字、人物、时间、链接；不放域名（贴图帖子外链不可跳）。
- 不用 `#`/`*`/`-` 等 Markdown 符号、不用 emoji、不用「•」「—」做项目符号。
- 厂商自测口径随原句一起带过来，不在摘要里补解释。
- 长度随速览自然伸缩，**不设字数上下限**；判断标准是「读完和读日报头部完全一致」。
- 速览改了，摘要必须跟着重生成（顺序：先定稿 HTML → 再从 HTML 抽速览写 txt，不要凭记忆写）。

**抽取方式**（不要手抄，避免与正文不一致）：

```python
import re, html
s = open('每日AI晨报_2026-11-18_公众号.html', encoding='utf-8').read()
seg = s[s.find('<!-- 本期速览 -->'): s.find('<!-- 第一部分 -->')]
ps = re.findall(r'<p style="[^"]*">(.*?)</p>', seg, re.S)
lines = ["牛马AI日报 · 2026 年 11 月 18 日", ""]
lines += [html.unescape(re.sub(r'<[^>]+>', '', t)).strip() for t in ps[1:]]
open('每日AI晨报_2026-11-18_摘要.txt', 'w', encoding='utf-8').write("\n".join(lines) + "\n")
```

## 八、贴图（图片消息）

摘要 txt 落盘后，再把它变成一组**图片**，作为公众号「图片消息」（`article_type=newspic`，俗称小绿书 / 贴图）推进草稿箱。图文消息与图片消息在草稿箱里各自独立，两条都建，发哪条由用户在后台点。（2026-11-20 用户定：「以后每天都这么做」）

**产物**：`贴图_{date}_01.jpg` … `贴图_{date}_08.jpg`，1080×1440（3:4，微信推荐比例），JPEG q90。生成脚本 `make_paste_images.py`，推送脚本 `paste_push.py`，均在工区根目录。

| 图 | 内容 |
|---|---|
| 01 | 封面：`DAILY AI BRIEFING` 眉标 + 主标题「牛马AI日报」+ `YYYY 年 M 月 D 日` + `2026.11.20 / FRI` + 红色短横线 + 「本期速览」+ 七个板块目录（圈号红、正文墨色） |
| 02–08 | 逐板块一张：圈号 + 板块名（62px 粗体）+ 细分隔线 + 该板块速览原句（50px，短句 60px） |

**文字口径**：卡片正文**就是摘要原句**，不缩写不改写；板块名单独做标题，正文段落只放 `｜` 之后那句。四周边距 90px，页脚左「牛马AI日报 · 2026.11.20」、右「02 / 08」。

**样式底线**：白底、墨色正文、**唯一强调色栏目红 #c0392b**、无装饰图形、无渐变、无卡片投影；标题左对齐顶格，与日报排版同一套气质。标题层与正文层之间的一条 2px 浅灰线是唯一的线。

**正文（图片消息的 content）**：速览七条原句逐行排列（段间空行）+ 末行「编发｜算法牛马」。纯文本，不用 HTML。
